# 子 Skill 输入输出协议

## 一｜选题研究 Skill

### 目标

通过多样本、反向样本和必要的账号基线验证，回答“这个选题能不能写、值得从哪些场景写、哪些内容机制可以迁移”，为后续创作提供可靠思路。研究深度服务创作判断，不以生成漂亮卡片为目标。

### 输入

- 选题想法；或
- 选题想法＋竞品笔记；或
- 一篇希望研究其可迁移机制的竞品笔记。

账号目标和已知限制可以附加；缺失时不得推测。

### 必须完成

1. 核验样本事实、发布时间、互动、内容、评论和必要的账号基线；
2. 使用多样本、未达本轮目标／反向样本收窄单篇爆款的偶然解释；
3. 区分用户需求、当前供给、账号势能、投流、时间和其他未知因素；
4. 总结爆款共同解决的问题、行文逻辑、内容节奏、痛点展开和结果兑现；
5. 判断需求是否真实、当前为何仍有创作空间、现有内容遗漏了什么；
6. 默认交接O1★；备选仅按用户要求提供；
7. 详细研究保留在附件，交接卡只保存下游必须继承的内容。

### 输出与停止点

1. 详细研究附件；
2. 先区分阻塞缺口与非阻塞剩余风险；阻塞缺口会改变选题或机会决定，非阻塞风险只限制强主张；
3. 只有形成至少一个负责任的机会且不存在阻塞缺口时，才按`02-标准选题交接卡.md`填写卡片；
4. 卡片保留需求与场景、当前创作空间、可迁移内容机制和本轮表达上限，不把“投流未排除”等研究过程用语原样留作用户待办；
5. 需要补证时不生成半成品卡，只提出最多三项真正阻塞下一阶段的补充请求。

附件、交接卡和用户可见回复分开保存；完整机会只在交接卡出现一次，附件保留证据、替代解释和研究边界，用户回复不重复前两份正文。达到“足以做本轮创作决定”即可交接，不追求排除所有现实混杂。输出后停止，等待用户确认按合同02预填的第4部分。运行状态只能是“需要补证／研究侧可交接／不建议推进”之一；补证最多三项，研究侧可交接时才生成正式卡。

## 二｜统一创作策划与内容生产

执行入口：[内容生产 Skill](../../../zhouyi-xhs-content-production/SKILL.md)。具体方法和字段只维护在该 Skill 的阶段参考，总控不复制。

### 阶段 A｜创作策划与方案

输入：有效标准选题卡（研究交接或用户独立研究同版卡），以及用户确认的最终机会、真实解决办法、当前状态、公开材料、必要条件／禁止承诺。

输出一份三部分创作方案：本篇创作决定、逐页内容方案、事实基础与表达边界。每页包含用户问题、本页任务、标题方向、关键信息、证据／截图建议、承接逻辑。以5—10页候选方案进入 `awaiting_content_plan_approval` 后停止，不再另交一份四部分简报，不提前生成视觉或最终平台文案。

统一方案获批后设 `content_plan_approved`；仅在用户已授权继续时进入阶段 B，本公开版不额外生成观察记录。

### 阶段 B｜视觉设计与平台发布文案

输入：用户明确批准且可定位的创作方案、方案列明的相关素材及直接适用规则。输出视觉版式、逐页设计与提示词、截图对照、统一规范、推荐与备用标题、正文、话题、置顶评论、答疑底稿和相对批准方案的主要变更，设 `production_ready`。

继承方案的页数、任务、顺序和主线；文档完成不等于图片生成或实际发布。实际发布后另补时间、账号、笔记ID、链接及成品版本。

### 历史兼容

本包不另带旧简报 Skill。只有旧简报时进入阶段 A；已有有效、明确批准的旧内容方案时，以该方案及继承简报、素材进入阶段 B。具体按内容生产主文件处理，不追改历史，不要求重新批准有效旧方向。
