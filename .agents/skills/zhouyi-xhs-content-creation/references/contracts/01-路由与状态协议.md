# 路由与状态协议

## 路由优先顺序

按顺序判断，命中后结束分支筛选，继续该分支已授权工作，不同时启动多个分支：

1. 用户维护方法、规则、版本或 Skill：转独立治理。
2. 当前候选创作方案尚未获批：停在 `awaiting_content_plan_approval`，处理审核或修改；用户明确批准当前版本时转为批准状态。
3. 当前创作方案已明确批准，用户要继续制作：转内容生产阶段 B。
4. 研究侧可交接且真实输入已确认：转内容生产阶段 A，输出统一创作方案。
5. 只有选题想法、竞品或希望复刻的笔记：转选题研究。
6. 信息仍不足以选择：最多请求三项真正影响路由的缺口。

“复刻”指研究可迁移机制，不移植身份、经历、案例或结果。自己的材料现成不能替代研究。

## 路由合同

| 路由 | 最低准入 | 主要停止点 |
|---|---|---|
| 选题研究 | 想法或至少一篇可定位竞品 | 研究附件与标准选题卡，确认预填真实输入 |
| 内容生产／阶段 A | 有效研究交接卡＋最终机会＋已确认真实方案、状态、公开素材和边界 | 三部分统一候选创作方案，等待一次批准 |
| 内容生产／阶段 B | 当前有效方案及版本已获明确批准 | 视觉、做图提示词及平台文案；实际制图与发布另计 |
| 独立治理 | 用户明确维护方法或 Skill | 执行用户批准范围，未批准部分展示具体修改再确认 |

## 两种研究入口

- `research_handoff`：研究 Skill 的标准选题卡，末尾五项按合同02预填并由用户确认。
- `standalone`：用户已自行研究，用同版卡只保留 O1；研究判断保留“用户研究／系统未复核”，同样确认五项真实输入。

两种入口使用同一准入；不维护第二套简化卡，也不把用户研究改写成系统验证。

## 旧项目迁移

- 历史候选简报或已批准简报尚无批准内容方案：转阶段 A，继承有效事实与已确认决定，补成统一方案；不重问旧方向，不把旧简报批准当作页面批准。
- 历史候选内容分配方案：继续审核，按需补足统一方案的事实与边界，批准点不增加。
- 历史内容分配方案已明确批准且仍有效：视作阶段 B 的批准输入，同时提供其继承简报与素材；不重走策划。
- 旧状态 `brief_in_progress`、`awaiting_brief_approval`、`brief_approved` 仅作历史线索，按实际产物判断上述去向，不追改历史文件。

## 批准与继续

阶段 A 完成后必须等待用户明确批准。获批后设为 `content_plan_approved`。

阶段 B 只读批准方案与相关素材，不回翻整套研究或失效版本重新策划。用户只要求确认而未授权继续时，记录批准后停止。

## 反馈路由

| 主要差异 | 返回位置 |
|---|---|
| 人群、场景、需求、选题空间或竞品机制判断有误 | 选题研究 |
| 主张、价值取舍、论证、真实方案、素材或边界有误 | 内容生产阶段 A |
| 成品标题、正文、图片或版本偏离批准方案 | 内容生产阶段 B |
| 正式规则冲突或反复造成偏差 | 规则问题提醒，等待用户决定独立治理 |
